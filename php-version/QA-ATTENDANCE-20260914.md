# 출퇴근 집중 QA — 2026-09-14

애플리케이션 코드를 수정하지 않고 점검했다. 사용자 휴대폰 테스트 DB와 운영 DB는 건드리지 않았으며, 새로운 SQLite DB에서 HTTP 요청으로 추가 상황을 재현했다. 이번 검증은 GPS 좌표를 제공하는 테스트 요청을 사용했으며 실기기의 위치 센서·권한 동작을 새로 검증한 것은 아니다.

## 재현된 문제

후속 수정: 아래 4건 모두 수정 및 회귀 검증을 완료했다. 열린 근무의 24시간 기준 상태를 화면마다 공통 사용하며, 출장 오류 재표시 시 장소·사유만 보존하고 GPS는 새로 측정한다. 자동 갱신에는 해당 권한 범위의 휴가 상태·종류·기간·삭제 여부도 반영한다. PC 퇴근 입력이 출근과 같은 현재 분이고 서버 시각은 출근보다 늦으면 저장 순간 서버 시각으로 기록한다. 과거 분의 입력과 역전 시각은 기존 검증을 유지한다. 최초 HTTP 재현 시나리오를 재실행하여 같은 분 PC 퇴근 HTTP 200, 휴가 변경 감지, 출장 입력 보존, 밤샘 상태 일치를 확인했다.

### 1. [P2] 날짜를 넘긴 근무 상태가 화면마다 다름

- 조건: 전날 23:00 출근, 다음 날 16:46까지 퇴근 없음(약 17.8시간).
- 대시보드는 `출근 전`, 개인 출퇴근 상단은 `근무 중`, 월별 기록은 `퇴근 누락`으로 표시한다.
- 원인: 대시보드는 오늘 날짜의 행만 상태 판단에 사용하고, 개인 화면은 열린 근무를 사용하며, 목록은 근무일이 오늘인지로 누락 여부를 구분한다.
- 영향: 야간 근무자가 현재 근무 중인지, 새 출근을 해야 하는지 혼동할 수 있다. 대시보드에는 이전 미퇴근 안내도 있으나 주 상태와 불일치한다.
- 수정 방향: 열린 근무와 누락 판단 기준을 공통으로 사용하고 근무 시작 날짜를 명시한다.
- 관련: app/ui.php renderDashboard(), app/attendance-views.php attendanceLabel()/renderAttendance().

### 2. [P2] 출장 GPS 검증 실패 후 근무 장소·사유가 초기화됨

- 절차: 출장 출퇴근 선택 → 사유 입력 → 위치 오차가 회사 경계와 겹치는 GPS 정보로 제출.
- 결과: HTTP 422와 함께 회사 출퇴근으로 돌아가고 입력한 출장 사유가 사라진다.
- 원인: 오류 페이지 렌더링 시 punchMode를 office, tripReason을 빈 문자열로 고정한다.
- 영향: 위치 재측정 전 출장 선택과 사유를 다시 입력해야 한다. 재시도 때 회사 출퇴근 상태로 잘못 제출하기 쉽다.
- 수정 방향: 검증 실패 시 사용자 입력을 보존하되 GPS 좌표는 다시 측정한다.
- 관련: app/attendance-views.php renderAttendance()의 attendance-mobile-fields.

### 3. [P2] 휴가 승인·취소로 달라진 근태 상태가 자동 갱신되지 않음

- 조건: 출근 기록이 있는 상태에서 해당 날짜 휴가가 승인된 상황을 DB fixture로 구성.
- 결과: 새로 조회하면 `휴가와 기록 중복`이 보이지만 attendance-revision 값은 이전과 동일하다.
- 원인: 변경 감지 값은 AttendanceHistory 개수와 오늘 날짜만 사용한다. 근태 표시가 의존하는 LeaveRequest 변경은 포함하지 않는다.
- 영향: 열어 둔 근태 화면의 휴가·충돌 상태가 오래된 상태로 남을 수 있다. 출퇴근 기록 자체의 동기화는 통과했다.
- 수정 방향: 근태 화면에 영향을 주는 휴가 변경도 변경 감지에 포함한다.
- 관련: app/attendance.php attendanceRevision().

### 4. [P3] GPS 출근 직후 같은 분에 PC 퇴근을 저장하면 기본 시각이 거부됨

- 재현: GPS 출근 시각 16:46:30, PC 퇴근 입력 기본값 16:46 → 그대로 확인 후 저장.
- 결과: HTTP 400, `퇴근은 출근보다 늦어야 합니다.`
- 원인: GPS는 초까지 저장하나 PC 입력은 분 단위라 16:46:00으로 변환된다.
- 영향: 실제로 출근 후 버튼을 눌러도 같은 분 동안은 기본값으로 퇴근할 수 없다. 빈도는 낮지만 기기 간 시간 정밀도가 다르다.
- 수정 방향: 시각 정밀도 정책을 통일하거나 동일 분의 입력 제한을 명확히 안내한다.
- 관련: app/attendance.php attendanceClock()/attendanceValidateTimes(), app/attendance-views.php entryTime.
