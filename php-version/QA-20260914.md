# 사이트 전체 QA — 2026-09-14

현재 작업 폴더의 PHP 버전을 격리 SQLite DB와 합성 계정으로 검사했습니다. 확인한 범위에서 업무를 막는 오류는 발견하지 않았으며, 잘못된 URL 입력으로 서버 경고가 발생하는 문제 1건을 수정했습니다.

## 발견 및 수정

| 우선순위 | 재현 | 원인과 조치 | 결과 |
| --- | --- | --- | --- |
| 낮음 | 관리자 로그인 후 `?page=employee&id[]=invalid` 또는 `?page=approvals&stage[]=invalid` 접근 | 배열 쿼리 값이 화면에서 문자열로 변환되어 PHP 경고 발생. 공통 진입점에서 배열 값을 제거하고 400 안내 응답 처리 | 3개 회귀 검사 추가, 재검사 시 PHP 경고 없음 |

수정 파일: `public/index.php`, `tests/http_test.py`. 배포 ZIP을 다시 생성하고 압축 해제 실행 검사를 통과했습니다. 외부 배포는 수행하지 않았습니다.

## 검증 범위의 한계

- 로컬 PHP 8.3 / SQLite 기준입니다. 실제 카페24 서버, MySQL/MariaDB, 운영 도메인의 HTTPS·쿠키 설정은 이번에 검증하지 않았습니다.
- 320/390px 검사는 브라우저 화면 폭 검사입니다. 실제 iOS/Android의 GPS 권한, 정확도, PWA 설치·업데이트는 실기기 검증이 필요합니다. GPS 자동 검사는 합성 좌표와 모의 브라우저 API를 사용합니다.
- 대량 데이터 성능, 장시간 동시 접속, 전체 접근성 표준 감사는 포함하지 않았습니다. 관리자 모바일 직원·근태 표의 내부 가로 스크롤까지 모두 제거했다는 의미는 아닙니다.
- 주요 변경·결재·카드·증빙 동작은 HTTP 회귀 검사로 검증했으며 모든 상태 조합을 브라우저에서 반복하지는 않았습니다.
