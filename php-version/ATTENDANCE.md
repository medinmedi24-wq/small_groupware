# PHP 출퇴근 기록

## 현재 방식 (2026-09-14)

- PC: 오늘의 출근·퇴근 시각을 각각 직접 입력합니다. 현재 한국 시간이 기본값이며 입력한 시간을 확인했다는 체크 후 저장합니다.
- 모바일: 위치 권한을 요청하고 GPS를 확인한 후 서버의 현재 시각으로 저장합니다. 회사 인터넷/IP는 GPS를 대신하지 않습니다.
- 출근을 저장하면 출근 입력은 잠기고, 비어 있는 퇴근만 새로 입력할 수 있습니다. 퇴근까지 저장하면 입력창이 사라집니다.
- 저장한 기록은 직원이 직접 수정·삭제할 수 없습니다. 누락·정정 신청에 변경할 시간과 사유를 입력하고 관리자가 승인해야 반영됩니다.
- 관리자는 본인 정정 신청을 처리할 수 없습니다. 다른 관리자가 처리해야 합니다.
- 기록에는 직접 입력 / 회사 반경 확인 / 출장 위치 기록을 구분합니다. 과거 회사 네트워크 기록도 기존 표시를 유지합니다.

PC·모바일은 브라우저 정보로 분기하며 iPad의 데스크톱 모드도 보완합니다. 기기 구분은 변조 방지 수단이 아니며 직접 입력은 직원의 신고 기록입니다.

## 관리자 근태 검색

모바일에서는 날짜별 직원 현황과 월별 출퇴근 내역을 카드로 표시합니다. 이름·부서·날짜·상태를 먼저 보여주며, ‘상세 정보’를 펼치면 출퇴근 시각과 기록 방식, 휴가·근무 기준을 확인할 수 있습니다. PC에서는 기존 표를 사용하고 두 화면 모두 같은 검색 결과를 표시합니다.

직원 이름(부분 일치), 부서, 근무 상태로 조회할 수 있습니다. 직원·부서는 날짜별 현황, 월별 내역, 정정 신청과 이력에 적용하고 근무 상태는 출퇴근 표와 CSV에 적용합니다. 날짜·월 변경과 신청 처리 후에도 검색 조건을 유지합니다.

‘기록 없음’과 ‘휴가만 있음’은 날짜별 현황에서 확인합니다. 월별 내역과 CSV에는 실제 출근 기록이 있는 날짜만 포함하며, CSV는 선택한 월과 검색 조건을 그대로 사용합니다.

## 입력·정정 규칙

PC에서 미래 시각은 입력할 수 없고 퇴근은 출근 이후여야 합니다. 이전 날짜의 누락은 정정 신청을 이용합니다. 전날 출근 후 자정을 넘겨 퇴근하면 오늘 입력한 퇴근 시각을 원래 근무일에 연결합니다. 24시간을 넘긴 미퇴근은 관리자 정정으로 처리합니다.

서버가 중복 출근·퇴근과 오래된 화면의 제출을 차단합니다. 정정 신청 후 원래 기록이 바뀌었다면 승인할 수 없으며 반려 후 다시 신청합니다. 정정 승인 전까지 원래 기록을 유지하고, 변경 전후 시간·신청 사유·처리자·시각을 이력으로 보관합니다.

승인된 종일 휴가에는 일반 출근을 차단하며, 반차는 기존 휴가 정보를 표시합니다. 정규 09–18시, 오전 반차 14–18시, 오후 반차 09–14시는 화면의 안내 기준입니다. 급여·야근 계산과 자동 결근 판정은 하지 않습니다.

## 모바일 위치 기준

송도 AIT센터(37.3796517, 126.6659428) 반경 150m 안에 GPS 오차 범위까지 들어와야 합니다. 최대 허용 오차 100m, 측정 유효 시간 2분입니다. 오차가 크면 한 번 더 측정합니다. 회사 밖 출장은 출장 출퇴근을 선택하고 출장지·사유를 입력합니다.

위치 거부·시간 초과·오프라인에서는 저장하지 않습니다. 서버도 위치를 독립 검증합니다. 브라우저 보고 좌표는 진위까지 보장하지 않으며 이동 경로·백그라운드 위치는 수집하지 않습니다. 운영에서는 HTTPS가 필요합니다.

## 저장·배포

PHP와 기존 직원 계정·업무 DB를 사용하며 별도 Node 서버가 필요하지 않습니다. 배포 전 DB와 비공개 storage를 백업하고, 배포 ZIP의 소스를 갱신하되 config/local.php와 DB·증빙 파일을 유지합니다.

첫 근태 접근 시 database/attendance-mysql.sql 또는 attendance-sqlite.sql로 필요한 테이블을 추가합니다. 이번 추가는 AttendanceManual이며 입력 시각과 실제 저장 시각을 따로 보관합니다. 기존 근태·GPS·회사 네트워크 기록은 삭제하지 않습니다. 생성 권한이 없는 운영 계정은 관리 도구에서 해당 SQL을 먼저 실행합니다.

원좌표·회사 IP는 비공개 DB에 보관하며 일반 화면·CSV에는 확인 방식만 표시합니다. GPS 시간과 일치하지 않는 기존·정정 기록은 GPS 미확인으로 표시합니다. 관리자 화면은 날짜별 현황과 월별 CSV를 제공합니다.

검증: `python tests/attendance_test.py`, `node --test tests/attendance-gps.test.cjs`, `python tests/package_test.py`. 별도 테스트 DB를 사용합니다. 로컬 검증은 SQLite 기준입니다.
# 대기 중인 정정 신청 수정·취소 (2026-09-14)

출퇴근 기록의 ‘누락·정정 신청’에서 본인의 검토 대기 건을 펼쳐 근무일, 출퇴근 시간, 다음 날 퇴근 여부와 사유를 수정할 수 있습니다. ‘신청 취소’를 하면 취소 상태와 이력을 보존하며 같은 날짜로 다시 신청할 수 있습니다. 관리자 승인 전에는 실제 출퇴근 기록이 바뀌지 않습니다.

이미 승인·반려·취소된 건과 다른 사람의 신청은 수정·취소할 수 없습니다. 수정 전에 열어 둔 관리자 승인·반려 화면이나 본인 수정·취소 화면은 새로고침 후 최신 내용을 확인해야 합니다. DB 구조 변경은 없습니다.
# 관리자 대시보드 정정 대기 안내 (2026-09-14)

관리자 대시보드 상단에 처리할 근태 정정 건수를 표시합니다. 모든 월의 검토 대기 신청을 합산하되, 본인 신청과 승인·반려·취소된 건은 제외합니다. ‘대기 신청 확인’을 누르면 근태 관리의 누락·정정 신청 영역으로 바로 이동합니다. 0건이면 대기 신청이 없음을 안내합니다.

# 휴대폰 GPS 기록과 PC 자동 반영 (2026-09-14)

휴가 승인·취소·기간 변경도 근태 자동 갱신에 반영합니다. 개인 화면에서는 본인의 휴가만 변경 감지에 포함합니다. PC에서 출근과 같은 현재 분으로 퇴근을 입력하면, 실제 저장 시각이 출근 이후인 경우 서버의 저장 시각(초 포함)으로 기록합니다. 과거 시각을 선택한 경우는 입력값을 유지하고 출근보다 늦은지 검사합니다.

휴대폰 브라우저와 PC에서 동일한 배포 서버에 같은 직원 계정으로 로그인합니다. 휴대폰에서 위치 권한을 허용하고 출근·퇴근을 누르면, 서버가 회사 반경과 위치 오차를 검증한 뒤 공통 근태 DB에 서버 시각으로 저장합니다. 휴대폰에서 접속 가능한 HTTPS 주소가 필요합니다. PC의 localhost 주소는 휴대폰에서 사용할 수 없습니다.

대시보드·출퇴근 기록·관리자 근태 화면은 보이는 동안 10초마다 변경 여부를 확인합니다. 탭으로 돌아오거나 인터넷이 다시 연결될 때도 확인합니다. 변경이 있으면 현재 검색 조건과 스크롤 위치를 유지해 페이지를 갱신합니다. 입력 중인 폼, 열린 대화상자, GPS 확인 또는 제출 중에는 자동 새로고침을 보류합니다. 입력 내용이 있는 경우 변경 알림을 표시하므로 저장 후 직접 새로고침합니다. 다른 직원의 변경 감지는 관리자 대시보드·근태 관리에만 허용됩니다.

첨부된 meditime-mobile 네이티브 앱은 별도 meditime-online API용이므로 이 웹 연결에 포함되지 않습니다. 실기기 GPS 측정은 HTTPS 배포 후 별도 확인이 필요합니다.

검증: `python tests/attendance_test.py`, `node --test tests/attendance-sync.test.cjs tests/attendance-gps.test.cjs`. 서로 다른 로그인 세션의 출근·퇴근 반영, 권한, 중복 방지, 입력 보호, 오프라인 복귀를 확인합니다.
