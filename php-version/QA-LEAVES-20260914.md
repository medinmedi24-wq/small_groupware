# 연차 집중 QA — 2026-09-14

기능 코드를 수정하지 않고 새로운 SQLite DB에서 HTTP 요청으로 재현했다. 운영 데이터 및 사용자 휴대폰 테스트 DB는 변경하지 않았다.

## 확인된 오류

### 1. [P1] 검토 후 바뀐 기간·일수가 오래된 승인 폼으로 처리됨

- 직원이 2026-12-14 하루 신청 → 팀장 승인 폼 보관 → 직원이 12/14~12/18, 5일로 변경 → 기존 팀장 승인 폼 제출.
- HTTP 200, 5일 신청이 관리자 승인 대기로 넘어갔다.
- 이어서 관리자가 5일 최종 승인 폼을 열고, 다른 편집으로 3일로 바뀐 뒤 기존 최종 승인 폼을 제출해도 HTTP 200으로 3일이 승인됐다.
- leave_decide는 단계와 상태만 확인하며 검토 당시 내용과 최신 내용을 비교하지 않는다. app/actions.php leave_decide, app/views.php leaveTable.
- 권고: 기간·종류·일수·사유 및 상태를 포함한 검토 토큰을 잠금 후 확인한다.

### 2. [P2] 오래된 수정 화면이 최신 휴가 기간을 덮어씀

- 11/2 하루 신청의 수정 화면을 연 뒤 다른 편집으로 11/2~11/4, 3일로 변경.
- 이전 폼에서 사유만 수정하고 제출하면 HTTP 200으로 다시 1일이 된다.
- leave_edit에는 내용 버전 비교가 없다. 이력은 남지만 변경 충돌을 예방하지 못한다.
- 권고: 수정 충돌 시 최신 내용을 재확인하게 하고, 오류 폼 재제출로 비교를 우회하지 않도록 한다.

### 3. [P2] 신청 후 회사 휴일이 바뀌면 과다 차감 가능

- 10/5~10/6을 2일 연차로 신청 → 관리자가 10/6을 회사 휴일로 등록 → 팀장·관리자 승인.
- 승인된 days는 2일, 같은 기간의 현재 leave-preview 계산은 1일이었다.
- 신청 시 계산한 days를 승인 시 재검증하지 않으며, 회사 휴일 변경도 영향을 받는 기존 신청을 확인하지 않는다.
- 권고: 휴일 변경 영향 목록을 확인시키고, 승인 시 현재 휴일 기준과 달라졌으면 재검토한다. 이미 승인된 신청의 재계산·보정 정책은 별도로 결정해야 한다.

- 추가로 잔여 1일인 테스트 직원의 서로 다른 1일 신청을 두 PHP 프로세스에서 동시 실행했다. 1건 저장, 1건 초과 차단, 총 예약 1일을 확인했다. 이 결과는 SQLite 단일 재현이며 MySQL 동시성 검증을 대신하지 않는다.

- 배포 테스트의 설치·기존 날짜 변환은 통과. MySQL 전용 동시성 분기는 별도 테스트 DSN이 없어 실행하지 않았다.
- 실기기 화면 및 한국 자정의 실제 날짜 전환을 이번 점검에서 새로 검증하지 않았다.

## 1·2번 수정 완료

- 휴가 종류·기간·일수·사유·결재 상태를 포함한 검토 토큰을 화면에 넣고, 사용자 잠금 후 최신 신청과 비교한다.
- 팀장/관리자 승인·반려, 수정, 본인 취소 및 관리자 승인 취소에 적용했다. 불일치 또는 토큰 누락은 HTTP 409로 차단한다.
- 수정·관리자 취소 오류 화면은 제출한 토큰을 유지해 새로고침 없이 재제출하는 우회를 막는다.

- 휴대폰 테스트 복사본에 PHP 소스 3개만 반영했다. 사용자 데이터는 변경하지 않았다.

## 3번 수정 완료 — 회사 휴일 변경 보호

- 평일 휴일 추가·삭제가 대기/승인 휴가 기간에 영향을 주면 HTTP 409로 변경을 차단한다. 취소·반려 신청과 주말은 제외한다.
- 차단 화면에서 영향받는 직원, 기간, 상태와 신청 확인 링크를 제공한다. 해당 날짜를 제외하도록 신청을 수정하거나 취소한 뒤 휴일 변경을 다시 진행한다. 기존 승인 일수를 자동 변경하지 않는다.
- 팀장 및 최종 승인 직전에 현재 휴일 기준으로 다시 계산한다. 저장된 일수와 다르면 승인하지 않고 수정/취소를 안내한다. 목록에도 현재 계산 일수와 재확인 표시를 제공한다. 반려는 계속 가능하다.
- 휴일 쓰기와 휴가 쓰기는 트랜잭션 시작 시 공통 관리자 잠금을 먼저 얻는다. SQLite는 쓰기 잠금, MySQL은 관리자 행 잠금을 사용하며 직원 관리와 동일한 관리자 잠금 순서를 따른다.
- 중복 휴일은 409, 이미 삭제된 휴일은 404로 안내한다.
- 격리 SQLite HTTP 회귀 테스트 392개 통과. 기존 데이터의 과다/과소 일수, 팀장/최종 승인, 반차 0일, 승인/대기 신청 충돌, 취소 후 휴일 변경, 주말 예외, 권한 및 CSRF를 검증했다. MySQL 동시성과 실기기 화면은 이번에 별도 검증하지 않았다.
- 휴대폰 테스트 복사본에 PHP 소스 3개 반영. 사용자 데이터 및 기존 휴일/신청은 변경하지 않았다.
